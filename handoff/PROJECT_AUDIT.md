## 1. Обзор проекта и текущая архитектура

Приложение представляет собой легковесную (LSUIElement / menu bar) утилиту для macOS, написанную на **Swift 5 + SwiftUI + AppKit**, с низкоуровневыми движками на **C++ (whisper.cpp, ggml)**.

### Высокоуровневая диаграмма архитектуры

```
[Пользовательский ввод]
  ├─ Global Event Tap (HotkeyMonitor: CGEvent / flagsChanged / keyDown / keyUp)
  └─ Menu Bar Popover / Settings Window (SwiftUI)
         │
         ▼
[DictationEngine (Оркестратор состояний)]
  ├── Машина состояний: .idle ⇄ .recording ⇄ .processing ⇄ .typing
  ├── AudioCapture (AVAudioEngine ➔ 16 kHz Mono Float32)
  │     ├── AudioLevelAnalyzer (RMS + Accelerate vDSP FFT Bands) ➔ RecordingHUD
  │     └── VADSegmenter (Silero VAD v5) [в live-режиме]
  ├── Транскрипция: WhisperBridge (whisper.cpp / Metal GPU / CPU) [ТОЛЬКО ЛОКАЛЬНО]
  ├── Обработка текста: TextCorrector (капитализация, пунктуация, словарь)
  ├── Вставка текста: TextInjector (CGEvent cghidEventTap ➔ Активное окно)
  └── Звуковой фидбек: SoundFeedback (NSSound / системные звуки)
```

### Точки входа и жизненный цикл
- **`Lyra/App/LyraApp.swift`**: Основная точка входа SwiftUI (`@main struct LyraApp: App`) со связкой через `NSApplicationDelegateAdaptor(AppDelegate.self)`.
- **`AppDelegate`**:
  - Создает и настраивает `NSStatusItem` в системном менюбаре.
  - Управляет `NSPopover` с контентом `MenuBarView(engine: engine)`.
  - Инициализирует синглтон-сервисы: `AudioLevelAnalyzer`, `DictationEngine`, `RecordingHUDWindow`.
  - Подписывается на нотификации открытия окон (`OpenSettings`, `OpenOnboarding`, `ClosePopover`).
  - Слушает `NSApplication.willTerminateNotification` для корректного освобождения Metal/ggml ресурсов (`prepareForTermination()`), чтобы избежать падения `GGML_ASSERT`.

## 2. Основные компоненты системы

### 2.1. Захват и анализ звука (`Lyra/Engine/`)
- **`AudioCapture.swift`**:
  - Использует `AVAudioEngine` и входной узел `inputNode`.
  - Устанавливает аудио-тап (`installTap(onBus: 0, bufferSize: 4096)`) на реальном аппаратном формате микрофона.
  - Выполняет конвертацию в стандартный для Whisper формат: **16000 Гц, 1 канал (моно), PCM Float32**.
  - Имеет защиту от переполнения памяти: жесткий лимит 5 минут (`maxRecordingSeconds = 300`).
  - Отслеживает смену конфигурации микрофонов (отключение гарнитуры, переключение частоты дискретизации) через `AVAudioEngineConfigurationChange`.
- **`AudioDeviceManager.swift`**:
  - Общается с CoreAudio (`AudioObjectGetPropertyData`) для получения списка микрофонов и их UID.
  - Позволяет выбирать конкретный микрофон или системный по умолчанию.
- **`AudioLevelAnalyzer.swift`**:
  - Вычисляет скользящее RMS-значение громкости (30 точек истории).
  - С помощью фреймворка Apple **Accelerate (`vDSP`)** выполняет быстрое преобразование Фурье (FFT на 1024 сэмплов с окном Ханна) и формирует 16 логарифмических частотных полос для визуализации.

### 2.2. Движок распознавания речи и локальные модели
- **`WhisperBridge.swift`**:
  - Swift-обертка вокруг C API библиотеки `whisper.cpp`.
  - Поддерживает Metal GPU ускорение на Apple Silicon (`arch(arm64)`) и фоллбэк на CPU (для x86_64).
  - Обеспечивает стриминг сегментов через C-колбэк `new_segment_callback`.
  - Реализует прерывание инференса через `CancellationFlag` и `abort_callback`.
  - Имеет прогрев Metal шейдеров (`warmup()`) пустым сэмплом тишины.
- **`ModelManager.swift`**:
  - Управляет скачиванием моделей GGUF/GGML с HuggingFace (`ggerganov/whisper.cpp` и `whisper-vad`).
  - Проверяет SHA-256 хеши скачанных файлов.
  - Поддерживает модели: Base (En/Multi), Small (En/Multi), Medium (En/Multi), Large-v3-Turbo, Silero VAD v5.
  - Хранит модели в `~/Library/Application Support/Lyra/Models/`.
- **`VADSegmenter.swift`**:
  - Реализует обнаружение голосовой активности с помощью модели Silero VAD для нарезки аудиопотока на речевые фрагменты в реальном времени.

### 2.3. Постобработка и вставка текста
- **`TextCorrector.swift`**:
  - Преобразование числительных (только для английского языка).
  - Словарь из ~150 технических акронимов и брендов (только для английского языка).
  - Капитализация первых букв предложений и базовая нормализация пунктуации.
- **`TextInjector.swift`**:
  - Прямой ввод текста в активное поле любого приложения через `CGEvent` (`keyboardSetUnicodeString`).
  - Разбивка на чанки до 32 UTF-16 символов с сохранением целостности суррогатных пар (корректный ввод эмодзи и специальных символов).
  - Выделенная последовательная очередь `com.lyra.typing` с барьером `flush()`.
  - Не затирает системный буфер обмена (`NSPasteboard`).

### 2.4. Глобальные горячие клавиши
- **`HotkeyMonitor.swift`**:
  - Использует `CGEvent.tapCreate` на уровне `cgSessionEventTap`.
  - Обрабатывает как модификаторы (`flagsChanged` — Option, Control, Command, Shift, Fn, CapsLock), так и стандартные клавиши (`keyDown`/`keyUp`).
  - Содержит вотчдог таймер для автоматического перезапуска тапа, если macOS временно деактивирует его.
- **`KeyCodeNames.swift`** и **`HotkeyRecorder.swift`**:
  - Таблица кодов клавиш и UI-контрол для переназначения горячей клавиши.

### 2.5. Пользовательский интерфейс и настройки
- **`Settings.swift` (`AppSettings`)**: Персистентность через `UserDefaults.standard`.
- **`SettingsView.swift`**: Окно настроек с боковой панелью:
  - Общие (General)
  - Речь (Speech)
  - Модели (Model)
  - Словарь (Vocabulary)
  - Горячие клавиши (Hotkeys)
  - Внешний вид (Appearance)
  - История (History)
  - Расширенные (Advanced)
  - Разрешения (Permissions)
  - О программе (About)
- **`RecordingHUDWindow.swift` & `RecordingHUDView.swift`**:
  - Плавающее неактивирующееся окно (`NSPanel`), поверх всех окон.
  - Текущий вид: прямоугольная карточка с визуализацией из 16 вертикальных полос (debug-like bars) и кнопкой статуса.

## 3. Анализ качества поддержки языков (Русский язык — приоритет №1)

### Текущее состояние
1. **Русский язык (`ru`)**:
   - В `LanguageCatalog.swift` для русского языка `defaultPrompt = ""` (пустая строка!). В то время как для английского передается огромный структурированный словарь на ~500 терминов.
   - В `TextCorrector.swift` флаг `usesEnglishPostProcessing = (language == .english)`. Соответственно, для русского языка **полностью отключена** коррекция технических терминов, акронимов и преобразование чисел!
   - Локальные многоязычные модели Whisper (Base/Small) на русском языке имеют высокий процент ошибок, путают падежные окончания и галлюцинируют знаки препинания при наличии шума. Модель Medium работает качественнее, но требует ~1.5 ГБ RAM и дает заметную задержку (1.5–3 секунды).
2. **Английский язык (`en`)**:
   - Максимально проработан в исходном коде: богатый словарь IT-терминов, конвертация чисел ("twenty one" -> 21), исправление регистра ("javascript" -> "JavaScript").
3. **Турецкий (`tr`) и Азербайджанский (`az`)**:
   - Присутствуют в каталоге, но не имеют кастомных словарей и правил постобработки. Для азербайджанского языка в каталоге предусмотрена модель `Large-v3-Turbo`, так как меньшие модели дают неудовлетворительное качество.

### Вывод по языкам
Внедрение API-провайдеров (OpenAI whisper-1, Groq whisper-large-v3, OpenRouter, Gemini) обеспечит **на порядок более высокое качество распознавания русской речи** с правильной расстановкой знаков препинания и распознаванием контекста. Дополнительно необходимо реализовать русский словарь профессиональной лексики и адаптировать `TextCorrector`.

## 4. Найденные проблемы и технический долг

### Критические архитектурные проблемы
1. **Жесткая привязка к локальному `whisper.cpp`**:
   - В коде полностью отсутствует уровень абстракции провайдеров (`TranscriptionService` / `SpeechToTextProvider`).
   - Нет возможности подключить OpenAI API, Groq, OpenRouter, Gemini или локальный сервер (Ollama, Whisper.cpp HTTP, vLLM).
2. **Отсутствие гибридного режима и Fallback**:
   - Если пользователь находится в офлайне или если API возвращает ошибку/таймаут, диктовка не работает, так как нет автоматического переключения на локальную модель.
3. **Несоответствие режима "Свободные руки" (Toggle) требованиям**:
   - Сейчас режим `.toggle` требует удерживать клавишу в течение 0.5–3.0 секунд (с таймером `scheduleToggleAction`), что неудобно и противоречит концепции hands-free.
   - Пользователю требуется: **одиночный клик — старт**, **повторный одиночный клик — стоп**.
4. **Устаревший UX окна записи (HUD)**:
   - Окно HUD появляется только во время записи (в покое полностью скрывается).
   - Дизайн окна — прямоугольная плашка с техническими полосками эквалайзера (FrequencyBar), выглядящая как отладочный виджет.
   - Нет компактного постоянного плавающего виджета ("Dynamic Island" / pill).
   - Нет плавных органических анимаций волны голоса (Siri/Apple Intelligence style).
   - Нет отображения Live Transcript непосредственно во время речи пользователя.
5. **Отсутствие гибкой настройки провайдеров**:
   - В настройках нет секции "Провайдер" (Base URL, API Key, Model, выбор провайдера, проверка соединения).

### Технический долг и мелкие проблемы
- `Lyra/en.lproj/` пуста (локализация интерфейса на английский не вынесена в строки, а захардкожена в SwiftUI представлениях).
- В `project.yml` захардкожены зависимости, но проект в основном собирается через универсальный `Makefile` вызовом `swiftc`.
- Отсутствие тестов сетевого слоя и провайдеров (текущие тесты в `LyraTests/` покрывают только VAD, парсер числительных и базовые настройки).

## 8. Выводы и стратегия реализации

Кодовая база содержит солидный и надежный низкоуровневый фундамент (захват аудио, инжекция текста, локальный whisper.cpp, обработка хоткеев).

Для успешной трансформации в коммерческий продукт **Lyra** необходимо:
1. **Внедрить абстракцию `TranscriptionProvider`**:
   - `OpenAICompatibleService` (поддержка OpenAI, Groq, OpenRouter, Gemini, локальных шлюзов).
   - `LocalWhisperService` (обертка над текущим `WhisperBridge`).
   - `HybridTranscriptionManager` (оркестрация: основной провайдер API + автоматический резервный переход на Local Whisper при сбоях сети).
2. **Переработать горячие клавиши и режим "Свободные руки"**:
   - Одно нажатие — старт записи, второе нажатие — остановка и вставка текста.
   - Поддержка клавиши `Left Option` по умолчанию и удобное переключение.
3. **Полностью переработать HUD**:
   - Постоянный изящный компактный элемент (Dynamic Island стиль) в режиме ожидания.
   - Плавное расширение при начале записи с органичной визуализацией голоса (Apple Intelligence / Siri стиль).
   - Вывод живого транскрипта во время записи.
4. **Обновить настройки приложения**:
   - Добавить полноценный раздел "Провайдер" (Base URL, API Key, Model Name, проверка подключения).
   - Привести структуру разделов в соответствие с ТЗ.
5. **Оптимизировать поддержку русского языка**:
   - Добавить системный русский словарь IT-терминов для промптинга модели.
   - Обеспечить высочайшую точность через современные облачные модели (Groq/OpenAI Whisper) с мгновенным локальным фоллбэком.
6. **Обновить брендинг и документацию**:
   - Создать стилизованные векторные ассеты созвездия Лиры и звуковых волн.
   - Вести непрерывный журнал разработки в `/handoff/DEVELOPMENT_LOG.md`.
